# 矿粉混样化验单核对

质检员把同批的矿粉混样化验单（JSON）上传到网页，程序判断这批数据是否相容；
出现矛盾时列出「单独更正即可恢复相容」的报告及其允许的混样含水率范围，
并允许提交候选报告的复测区间（只有换用后整批相容才保存）。

## 运行

```bash
docker compose up --build
# 浏览器打开 http://127.0.0.1:8000
```

数据保存在命名卷 `moisture-data`（容器内 `/data/moisture.db`，SQLite），
`docker compose down` 不会丢；要清空加 `-v`。

本地不开 Docker 时：

```bash
python3 -m pip install -r requirements.txt
DATABASE_PATH=./data/moisture.db python3 -m uvicorn app.main:app --port 8000
```

## 判定模型

- 每个原样有一个未知含水率 `x_s ∈ [0,100]%`，凡使用该原样的报告共用同一个值。
- 报告 `r` 的混样含水率是各原样取用克数的加权平均：
  `y_r = Σ m[r,s]·x_s / Σ m[r,s]`，必须落在该报告实测闭区间 `[low_r, high_r]` 内。
- 整批相容 ⇔ 存在一组 `x_s` 同时满足全部报告的区间。这是线性可行性问题，
  用 `scipy.optimize.linprog`（HiGHS）求解。
- **候选报告**：整批不可行，但去掉该报告后其余报告可行。这类报告单独复测就可能
  恢复相容。对每个候选，还求「其余报告允许的混样含水率范围」
  `[min y_r, max y_r]`（对 `y_r` 做两次 LP）；换用后的闭区间只要与该范围有交集，
  整批就相容。
- 若没有任何候选，提示扩大复测，并给出「至少需要同时更正几份报告」的提示
  （只枚举 1～2 份的组合，避免组合爆炸；提示里不会声称超过 2 份的具体数目）。

## 复测保存规则

提交复测区间时，在 SQLite 写锁内完成校验：

1. 页面上的批次版本号与库中不一致 → 不保存，提示「页面依据的数据已有更正」；
2. 区间不在 `0%～100%` 或下限大于上限 → 不保存；
3. 该报告已不是候选（整批已变化，或整批现在已经相容）→ 不保存，保持现状；
4. 换用后整批仍不相容 → 不保存，保持现状，提示「复测仍与其他报告矛盾」。

只有第 4 步通过才写入 `retests` 记录、更新该报告区间并递增批次版本号。
原始化验区间单独保存在 `original_low/original_high`，页面上同时显示「原报」值，
复测历史不会丢失。

## 上传格式

同批最多 24 份报告、12 个原样；可上传多个文件或直接粘贴 JSON。

```json
{
  "batch_name": "批次名称（可选）",
  "reports": [
    {
      "report_no": "BG-001",
      "samples": [
        {"sample_no": "YP-01", "grams": 50},
        {"sample_no": "YP-02", "grams": 30}
      ],
      "interval": [3.1, 3.4]
    }
  ]
}
```

兼容写法：`low`/`high` 直接写在报告里，或 `"moisture": {"low":…, "high":…}`；
原样写成 `{"YP-01": 50, "YP-02": 30}`；顶层直接是报告数组或单份报告对象。

示例数据见 `examples/`（也可是网页上的下载链接）：

| 文件 | 预期结果 |
| --- | --- |
| `compatible.json` | 整批通过，给出各原样可行含水率 |
| `mixed_conflict.json` | 矛盾，`BG-2026-102` 为唯一候选，允许范围 4.69%～4.83% |
| `no_candidate.json` | 矛盾且无单独候选，提示至少同时更正 2 份、扩大复测 |
| `review_package_example.json` | 外协复核包示例（由 compatible.json 选 YP-01/YP-02 出包） |

## 代码结构

```
app/analysis.py    线性模型、可行性判定、候选与允许范围
app/projection.py  精确有理数 Fourier–Motzkin 消元与二维半平面裁剪
app/package.py     复核出包 JSON 的生成、解析与两项读数核验
app/parsing.py     JSON 上传解析与校验（≤24 份、≤12 原样、0～100%）
app/db.py          SQLite 表结构、批次/报告/复测记录、原子写入
app/main.py        FastAPI 路由
app/templates/     Jinja2 页面
app/static/        样式与示例 JSON
tests/             分析、投影、出包、解析、格式化、网页流程测试
```

## 外协复核出包与收件核验

外协实验室复核两个矿粉原样时，需要判断两项实测含水率能否**同时成立**：
即是否存在其余原样的某组含水率，使整批化验单全部满足。系统把整批线性系统
精确投影到所选的两个变量上，外协方无需访问原批次即可核对。

### 出包（批次页）

- 批次含 **2～4 个原样**时，批次页出现「外协复核出包」面板，选择两个**不同**的
  原样后下载 JSON；整批互相矛盾时拒绝出包并说明原因，必须先复测更正到整批相容。
- 出包与页面修订号在同一份已提交数据上完成；修订号过期时拒绝，提示重新加载。
- JSON **只含**批次号、修订号、两个原样编号和线性不等式，系数为精确分数
  （整数省略分母），形如：

```json
{
  "batch_no": 1,
  "revision": 1,
  "samples": ["YP-01", "YP-02"],
  "inequalities": [
    {"a": "10", "b": "10", "c": "83"},
    {"a": "-10", "b": "-10", "c": "-77"}
  ]
}
```

每条不等式表示 `a·x₁ + b·x₂ ≤ c`（`x₁/x₂` 依次对应 `samples` 中两个原样的
含水率百分数）。0%～100% 的边界同样以不等式给出；可行域缩成**线段或单点**时，
等式拆成一对反向半平面，仍按闭区间判定（边界读数算通过）。

### 数学方法

- 库中现用克数与实测区间的十进制值经 `Fraction(str(...))` 转为精确有理数，
  报告约束为按克数加权的混样含水率 `Σ m·x / Σ m ∈ [low, high]`。
- 对未选中的原样变量依次做 **Fourier–Motzkin 消元**，得到仅含所选两项的不等式；
- 再用精确半平面裁剪（Sutherland–Hodgman）对 `[0,100]²` 求交，输出无冗余的
  棱面描述，并正确处理多边形、线段、单点与空集（整批矛盾）四种结局。
- 全部计算为有理数运算，不存在浮点容差；投影与 HiGHS 线性规划在数百组随机
  批次上交叉验证，结论零分歧。

### 收件核验（`/verify` 页，无需原批次）

1. 上传复核 JSON（或粘贴 JSON）；
2. 填写两个原样的含水率读数（十进制如 `3.15`，也接受分数如 `17/4`），
   每项限定 0%～100%；
3. 逐条不等式给出左端精确值与满足/违反结论：全部满足则**通过**，
   任一违反则**拒绝**并标出违反项。

JSON 解析严格：顶层只允许 `batch_no/revision/samples/inequalities` 四个字段，
不等式只允许 `a/b/c`（可附 `"op": "<="`），未知字段、非正整数批次/修订号、
两个相同原样、零系数等一律拒绝。

示例：`examples/review_package_example.json`（也可在核验页直接下载）。
